## How this list was built, and what it excludes

1. **Harvest.** 22 arXiv queries over the submission window returned 1639 unique papers.
2. **Code links from the abstract.** Only 103 papers (6 %) print a code URL in the abstract or the author comment. Taking that as "papers with code" would have missed most of them.
3. **Reverse lookup.** Asking GitHub which repositories cite each arXiv ID in their README recovered many more, bringing the total with a resolvable repository to 331.
4. **Aggregator removal.** 54 repositories were dropped as paper lists rather than paper code (`*-arxiv-daily`, `awesome-*`, or any repository cited by >= 3 different papers). This removed 140 papers whose only "code" was a listing.
5. **Relevance filter.** 146 papers were dropped as belonging to neighbouring fields that share vocabulary (robot locomotion, speech synthesis, network intrusion detection).

**Every repository below was resolved through the GitHub API on the generation date**: it exists, and its licence, size, star count and last-push date are recorded as returned. That is a deliberately low bar -- it means "the code exists", not "the code reproduces the paper". None of these repositories were executed. The `usability` column scores the *artefact* (licence, size, activity, community), never the research.

### Caveats you should read before citing this list

- A repository found by README search is **probably** the paper's code, but it can also be a third-party reimplementation or a student's course project. The `found` column records which signal matched: `abstract` means the authors themselves pointed at it.
- `no licence` is not a formality. A public repository without a licence grants no reuse rights at all. 27 of the entries below are in that state, so they can be read for method detail but not vendored into a product.
- arXiv abstracts frequently promise code that was never published. The reverse lookup is what separates a promise from a repository.
